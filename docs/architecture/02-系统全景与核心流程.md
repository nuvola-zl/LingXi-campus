# 系统全景：模块划分与核心流程

> 项目：Haze-AI-Hub 后端
> 说明：本文整理自开发中期的一次系统全貌梳理（借助 AI 工具扫描代码库后生成，经我逐模块核对修正）。适合作为了解整个后端架构的入口文档。

## 一、项目概览

| 项目 | 详情 |
| --- | --- |
| 技术栈 | Java 17 + Spring Boot 3.4.5 + Spring AI 1.1.2 + MyBatis-Plus + PostgreSQL + Redis |
| AI 能力 | 阿里云 DashScope（通义千问）、通义 Wanx 图像生成、text-embedding-v3 向量化、qwen3-rerank 重排序 |
| 架构模式 | 多模块 Maven 工程，DDD 分层：ai-common → ai-domain → ai-infrastructure → ai-server |

## 二、四大模块职责

```text
┌─────────────────────────────────────────────────────────┐
│  ai-server（唯一的 Spring Boot 应用）                     │
│  所有 HTTP 接口、业务逻辑、Skill 框架都在这里              │
│  启动类：AiServerApplication                             │
├─────────────────────────────────────────────────────────┤
│  ai-domain（数据层）                                      │
│  只管：实体定义 + Mapper 接口 + DTO                       │
│  不管：任何业务逻辑（没有 Service）                        │
├─────────────────────────────────────────────────────────┤
│  ai-infrastructure（技术基础设施）                         │
│  只管：缓存、OSS 存储、JWT 配置、SSE 推送                  │
│  对上层屏蔽技术细节                                       │
├─────────────────────────────────────────────────────────┤
│  ai-common（纯工具层）                                     │
│  只管：常量、统一返回格式、异常类、纯 Java 工具             │
│  零 Spring 依赖                                          │
└─────────────────────────────────────────────────────────┘
```

| 模块 | 职责 |
| --- | --- |
| ai-common | 通用工具：JWT 工具、SHA256 加密、注解（@RequireRole）、ThreadLocal 上下文（BaseContext）、统一响应体（Result）、Jackson 配置 |
| ai-domain | 领域模型：Entity/Mapper（MyBatis-Plus）、DTO、枚举、DAG 引擎核心、AOP 切面（RoleCheckAspect）、类型处理器（JSONB/Vector） |
| ai-infrastructure | 基础设施：OSS 配置、JWT 属性、DashScope/Wanx 属性绑定、缓存工具 |
| ai-server | 启动模块：Controller、Service、Handler 链路、DAG 节点实现、文件解析器、Redis Stream 消费/生产 |

依赖方向：`ai-server → ai-domain → ai-infrastructure → ai-common`（单向，无循环）。

## 三、核心数据表（ai-domain/ai/entity/）

| 实体类 | 表 | 用途 |
| --- | --- | --- |
| ChatSession | chat_session | 一次对话会话，属于某个用户，可以有 groupId 分组 |
| ChatMessage | chat_message | 会话里的每条消息（用户问的、AI 答的） |
| Group | chat_group | 会话分组，类似文件夹 |
| Model | ai_model | 可用的 AI 模型列表（deepseek-v3、qwen-plus...） |

| KbMedia | kb_media | 上传到知识库的文件（PDF/Word/图片等） |
| KbChunk | kb_chunk | 文件解析后的文本分块，带向量 embedding |
| Attachment | chat_attachment | 聊天附件（比如 AI 生成的图片） |

## 四、认证鉴权体系

```text
请求 → CorsFilter (全放行)
     → JwtTokenInterceptor (拦截 /api/**, /admin/**, /hr/**, /dag/**)
         ├─ 从 Authorization 头取 Token
         ├─ JWT 解析出 userId + roleType
         ├─ 写入 BaseContext (ThreadLocal)
         └─ 放行 / 返回 401
     → RoleCheckAspect (拦截 @RequireRole 注解的方法)
         ├─ 从 BaseContext 取真实角色
         ├─ 对比注解声明的角色
         └─ 不匹配 → 抛异常
```

三种角色：EMPLOYEE（普通员工）、ENGINEER（工程师）、ADMIN（管理员）。

关键文件：

- 拦截器：`interceptor/JwtTokenInterceptor.java`
- 切面：`aspect/RoleCheckAspect.java`
- 注解：`common/annotation/RequireRole.java`
- JWT 工具：`common/utils/JwtUtil.java`

## 五、核心工作流

### 流程 1：AI 对话（核心流程）

```text
POST /api/v1/ai/text-chat  (SSE 流式)
     │
     ├─ domain == "HR"
     │   └─ handleDomainChat() → hrChatClient (ChatClient with HrTools)
     │       工具：请假提交、打卡补卡查询
     │
     ├─ domain == "ADMIN"
     │   └─ handleDomainChat() → adminChatClient (ChatClient with MeetingRoomTools + DeviceTools)
     │       工具：会议室查询/预订、设备申请
     │
     └─ domain == "IT"  (主流程)
         ├─ ChatPipeline.prepare(): 创建/复用会话，保存用户消息
         ├─ IntentDetectionService.analyzeIntentReactive(): 意图识别
         │   （LLM 优先 → keyword 回退）
         ├─ HandlerRegistry.findFirstMatch(): 匹配 Handler
         │
         ├─ intent == "ticket_create" → TicketCreateHandler
         │   （多轮状态机: SUGGESTING → COLLECT → CONFIRM → EXECUTED）
         │
         ├─ intent == "ticket_query|ticket_urgent|ticket_close|ticket_abandon"
         │   → TicketActionHandler
         │
         ├─ intent == "knowledge_qa" → KnowledgeQAHandler
         │   （RAG 检索：BM25+向量混合检索 → RRF 融合 → Rerank → LLM 生成）
         │
         ├─ intent == "image_generation" → ImageGenerationHandler
         │   （通义 Wanx → OSS 存储 → 返回图片 URL）
         │
         └─ 其他/兜底 → DefaultChatHandler
             （直接调用 DashScope ChatModel 流式回复）
```

| 层 | 文件 |
| --- | --- |
| Controller | `ai/controller/ai/ChatController.java` — /api/v1/ai/text-chat |
| Service | `ai/service/impl/ChatServiceImpl.java` — 分流路由 |
| Pipeline | `Pipeline/ChatPipeline.java` — 会话准备/消息最终化 |
| 意图识别 | `ai/service/impl/IntentDetectionServiceImpl.java` |
| Handler | `handler/HandlerRegistry.java`, `DefaultChatHandler.java`, `TicketCreateHandler.java`, `TicketActionHandler.java`, `ImageGenerationHandler.java`, `KnowledgeQAHandler.java` |
| 记忆 | `config/JdbcChatMemory.java` — 从 DB 加载历史消息 |

权限：所有登录用户（无特殊角色要求），JWT 认证即可。

### 流程 2：知识库（Astra）RAG

知识库管理：

```text
POST   /api/v1/astra/libraries        ← @RequireRole("ADMIN")  创建知识库
GET    /api/v1/astra/libraries        ← 列表（带 Caffeine+Redis 缓存）
PUT    /api/v1/astra/libraries/{id}   ← @RequireRole("ADMIN")  编辑
DELETE /api/v1/astra/libraries/{id}   ← @RequireRole("ADMIN")  删除
```

文件上传与解析：

```text
POST   /api/v1/astra/media            ← @RequireRole("ADMIN")  上传文件
       ├─ OSS 存储原始文件
       ├─ RedissonStreamProducer 发送解析任务到 Redis Stream
       └─ AstraParseConsumer 消费任务
            ├─ FileParserFactory → PdfFileParser / WordFileParser / TxtFileParser / MarkdownFileParser
            ├─ ChunkingService 切分文本
            ├─ DashScopeEmbeddingModel 向量化 (1024维)
            └─ 写入 kb_chunk (pgvector)

GET    /api/v1/astra/media/{mediaId}/stream  ← SSE 订阅解析进度
```

知识库问答：

```text
POST   /api/v1/astra/chat             ← 流式 SSE
       ├─ QueryRewriteService: 用 DashScope 改写用户问题
       ├─ HybridVectorStore: BM25（PostgreSQL tsvector）+ 向量（pgvector cosine）双路检索
       ├─ RRF (Reciprocal Rank Fusion) 融合排序
       ├─ qwen3-rerank 重排序（可选，开关）
       └─ astraClient (ChatClient) 流式生成回答
```

| Library 服务 | `ai/service/impl/AstraLibraryServiceImpl.java` |
| Media 服务 | `ai/service/impl/AstraMediaServiceImpl.java` |
| 搜索服务 | `ai/service/impl/AstraSearchServiceImpl.java` |
| 向量存储 | `vector/HybridVectorStore.java` |
| 消费者 | `consumer/AstraParseConsumer.java` |
| 生产者 | `producer/RedissonStreamProducer.java` |

```text

  POST /api/v1/ai/text-chat    ← AI 对话中通过意图识别自动触发
       └─ intent == "ticket_create" → TicketCreateHandler (多轮收集)
       └─ intent == "ticket_query"  → TicketActionHandler
  GET  /api/ticket/list         ← 用户查看自己的工单
```

## 六、重点设计补充

### 1. DAG 引擎（domain/dag/DagEngine.java）

一个通用 DAG 执行器，用于设备申领流程：

- 拓扑排序后并发执行节点（CompletableFuture）
- 条件节点（ConditionNode）动态路由
- 通过 sys_dag_execution 表实现幂等和断点恢复
- WaitPurchaseNode 是异步节点，执行时挂起，等待外部 ADMIN 调用恢复

### 2. 工单创建状态机（TicketCreateServiceImpl）

基于 Redis 存储的 4 态流转：`SUGGESTING → COLLECT → CONFIRM → EXECUTED`。每个状态对应不同轮次的对话处理逻辑，Conversation ID = `sessionId_ticket_create`。

### 3. 知识反馈闭环（TicketKnowledgeFeedbackService）

工单关闭后自动触发：

1. LLM 总结工单 + 工程师评论 → 知识条目
2. 向量相似度去重（与已有 kb_chunk 比较）
3. 新增/更新 kb_chunk

### 4. 缓存体系

| 缓存 | 类型 |
| --- | --- |
| 模型列表 | Caffeine（30min TTL） |
| 分组列表 | Caffeine（30min TTL） |
| 知识库列表 | Caffeine（30min TTL） |
| 知识库详情 | Caffeine（30min TTL）+ Redis 穿透 |
| 服务目录关键词 | 内存 Map（手动刷新） |
| 工单创建状态 | Redis（会话级，有 TTL） |

## 八、核心设计思路总结

IT / HR / ADMIN 三大 AI 对话域分流：IT 域走「意图识别 → Handler 链路」的复杂 Pipeline，HR/ADMIN 域直接用 ChatClient + Function Calling。同时有一个完整的 DAG 引擎驱动设备申领审批流程，以及一个双路混合检索（BM25 + 向量）的 RAG 知识库系统。
