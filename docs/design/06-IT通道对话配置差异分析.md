# IT 通道对话配置差异分析：裸调模型是有意为之还是配置缺失

> 项目：Haze-AI-Hub · AI 对话链路
> 主题：IT 通道（DefaultChatHandler）与 HR/Admin 通道（ChatClient）在对话配置上的差异分析
> 状态：**分析结论已确认，是否补齐尚未实施**（见文末结论）
> 说明：以下差异对比由我提出「IT 通道直接使用原始模型，有配置问题吗？」这个问题后，让 AI 扫描三条通道的代码得出，经我对照源码逐项核实。

## 一、问题

IT 通道的通用对话直接调用原始 ChatModel（qwen-flash），没有像 HR/Admin 那样通过 ChatClient 封装。这是配置缺失还是有意设计？

## 二、差异对比

| 配置项 | IT 通道（DefaultChatHandler） | HR/Admin 通道（ChatClient） |
| --- | --- | --- |
| System Prompt | 没有，只传了用户消息+历史 | 有（HR_SYSTEM_PROMPT / ADMIN_SYSTEM_PROMPT） |
| 时间上下文 | 没有 | 有（当前时间、日期、用户ID等） |
| Tool 注册 | 没有 | 有（HR 有 HrTools，Admin 有 MeetingRoomTools + DeviceTools） |
| ReasoningContentAdvisor | 没有 | 有 |
| 模型/温度/token | qwen-flash, temp=0.8, 2000 token | 走 DashScopeChatOptions，由外层动态覆盖 |

## 三、代码佐证

IT 通道构建 Prompt 的方式（DefaultChatHandler.java:51-78）：

```java
// 只加了历史消息 + 当前用户输入，没有 SystemMessage，没有时间上下文
historyMessages.add(new UserMessage(ctx.getPrompt()));
Prompt chatPrompt = new Prompt(historyMessages, runtimeOptions);
```

而 HR/Admin 在每次请求时会注入时间上下文：

```java
String timeContext = String.format(
    "【当前时间上下文】现在时间是 %s（%s）%s。...当前用户ID：%d。",
    todayStr, weekDay, timeStr, ..., userId);
promptBuilder.messages(new SystemMessage(timeContext));
```

## 四、分析结论

也就是说：IT 通道的模型不知道自己是谁、今天几号、当前用户是谁、有什么工具可用——它只是裸调了 qwen-flash。

**但这不一定是 bug。** IT 通道走的是「意图识别 → Handler 分发」的链路（工单、知识库、图片等），兜底到 DefaultChatHandler 的通用对话场景可能确实不需要这些配置。真正的风险在于行为不一致：同样是闲聊，IT 入口和 HR 入口的回答质量、上下文感知能力会有明显差异。

**我的判断**：如果后续希望和 HR/Admin 对齐行为（尤其是让兜底对话也能感知时间和用户身份），应该创建一个 `itChatClient` bean 统一配置，而不是让 DefaultChatHandler 继续裸调。此项暂列待办，未实施。

## 五、待办与演进方向

- [ ] 评估 IT 兜底对话是否需要 System Prompt 与时间上下文
- [ ] 若需要，创建 `itChatClient` bean，与 hrChatClient / adminChatClient 配置方式对齐
- [ ] 统一三个域的 ReasoningContentAdvisor 行为
